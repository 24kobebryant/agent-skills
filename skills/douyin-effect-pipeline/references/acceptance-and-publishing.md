# 验收、检测与发布

## 六层证据

每层独立记录，不得用上一层代替下一层。

| 层级 | `passed` 的最低标准 |
|---|---|
| 源文件 | 改动存在于正确工程，素材和 GUID/sidecar 对应 |
| 编译 | 当前版本的脚本或图逻辑编译成功，无阻断错误 |
| 编辑器预览 | 当前工程真实运行，相关路径可复现 |
| 手机预览 | 抖音/预览端完整操作一局，视觉和热区可用 |
| 特效检测 | 在当前修改版本上完成检测并显示通过 |
| 平台提交 | 最终表单提交后出现明确成功反馈 |

`not_run` 表示没有执行；`blocked` 表示尝试过但被外部条件阻断。不要将二者写成 `passed`。

## 完整试玩清单

- 第一帧能看懂目标和危险；
- 启动方式与提示一致；
- 每个方向键、按钮或手势都有足够热区；
- 边界和碰撞没有卡死或穿模；
- 敌人/系统行为符合规格；
- 进入胜利区域立即触发胜利；
- 失败触发稳定且文案准确；
- 结算后不会继续接受错误输入；
- 重拍、重进或约定操作能重新开始；
- 第二局状态完全重置；
- 常见屏幕尺寸下关键内容不被拍摄 UI 遮挡。

## 发布资料

发布前展示或核对：

- 特效名称；
- 触发提示；
- 默认摄像头方向；
- 女性图标和男性图标（若当前表单要求）；
- 特效描述、分类和标签（若当前表单要求）；
- 素材/IP/音乐授权；
- 当前特效检测结果。

不要依赖历史表单值。更新版本时也要重新核对文案、图标和检测是否对应当前工程。

## 提交边界

- 用户只说“帮我做好”：做到可提交并展示最终值，等待提交授权。
- 用户明确说“帮我提交”“发布这个特效”：可执行正常上传和最终提交。
- 遇到协议勾选、身份认证、验证码、付费或不可逆授权时，停下说明具体步骤，让用户处理。

## 成功判定

以下都不等于已提交：

- 工程保存成功；
- 场景加载成功；
- 素材上传成功；
- 包体上传成功；
- 检测通过；
- 表单已填完；
- 点击了提交按钮但没有回执。

只有看到明确的提交成功状态、审核任务或可回读的版本记录，才报告“已提交”。审核通过是另一个后续状态。
