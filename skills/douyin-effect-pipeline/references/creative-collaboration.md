# 创意共创方法

## 目标

让用户从一句模糊想法自然走到可制作决定，同时保持主动提案、低沟通负担和快速实物反馈。

## 第一次回应

先做四件事：

1. 用一句话复述观众会经历什么，不复述实现细节。
2. 指出这个梗最可能成立的传播点。
3. 根据已知事实给出 2–3 个方向和一个明确推荐。
4. 只问会改变首个原型形态的 1–3 个问题。

不要先索要完整 PRD、所有素材、几十项偏好或技术参数。

## 决策树

按依赖关系展开，通常顺序如下：

1. **情绪目标**：紧张、搞笑、爽感、反转还是炫耀结果。
2. **体验主体**：用户本人、卡通替身、场景角色或物体。
3. **唯一操作**：点击、滑动、方向键、张嘴、摇头、姿态或无需操作。
4. **核心循环**：用户做什么，系统立即怎样回应。
5. **结束状态**：胜利、失败、结果卡和重玩。
6. **视觉识别**：第一眼能否看懂角色、目标和危险。
7. **传播理由**：结果是否值得录屏、比较、挑战或模仿。
8. **风险和成本**：平台能力、制作量、IP/肖像和审核表达。

只询问当前前沿。比如操作未定时，不要追问方向键尺寸；重玩方式未定时，不要先写结算文案。

## 问题格式

每轮最多 1–3 题，给出推荐和原因：

```text
Q1：用户要不要露脸？
A 不露脸，纯卡通角色（推荐）：梗更完整，也降低拍摄门槛。
B 露脸：代入感强，但会占用画面并增加识别依赖。
```

允许用户只回复 `A/B`。如果用户用自然语言修改选项，以用户表达为准，不强迫回到选项。

## 创意卡

每个方向统一输出：

```text
名称：
三秒钩子：
唯一操作：
成功 / 失败：
传播点：
制作成本：低 / 中 / 高
同质化：低 / 中 / 高
审核/IP 风险：低 / 中 / 高
仍待验证：
```

三个方向必须机制上不同，不能只是换皮、换颜色或换角色。

## 发散与收敛

发散时从这些轴组合，但不要全塞进一个方案：

- 追逐、躲避、选择、节奏、排序、预测、反应、收集、身份反转；
- 单局挑战、随机结果、好友比较、失败梗、结尾反转；
- 角色替身、环境变化、画面遮挡、尺度差、物理夸张。

收敛时优先级为：

1. 三秒能否看懂；
2. 一个动作是否足够玩；
3. 失败或成功是否有记忆点；
4. 像塑是否能稳定实现；
5. 是否能在一轮制作内验证；
6. 是否存在不可接受的审核/IP 风险。

## 什么时候停止提问

出现任一情况就转原型：

- 用户连续两次说“感觉不对”，但无法描述具体参数；
- 争论的是画面、手感、节奏或好不好笑；
- 两个方案语言上难分高下；
- 一个低成本实物能在十分钟到一小时内回答问题。

原型只回答一个问题，明确标记为临时，不提前做完整美术、兼容性和发布包装。

## 反馈归因

用户否定版本时先复述：

```text
我理解你否定的是 [创意/视觉/玩法/操作/实现]，保留的是 [...]。
下一版只改变 [...]，用它验证 [...]。
```

如果用户说“太复杂”，删除机制而不是只简化说明。如果用户说“没趣味”，先改变核心循环或结尾反馈，不要继续打磨边框、字体和质感。
