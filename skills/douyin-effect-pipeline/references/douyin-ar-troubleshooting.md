## 1. 工程身份

症状：打开后是默认女人摇头、旧版本、模板内容或完全不同的特效。

检查：

- 从 `effect.dyehpj` 读取安全字段 `name`、`version`、`projectID`；不要输出上传 URL、URI、Cookie 或其他凭据。
- 确认当前窗口对应的绝对工程路径。
- 区分工作副本、修复副本、发布副本和模板副本。
- 从最新编辑器日志寻找 `Open project successfully` 或等价加载记录。

没有工程路径证据时，不要开始编辑或提交。

## 2. 进程与窗口

症状：每次打开出现两个像塑图标、自动化总控制错窗口、同一工程偶发损坏或加载失败。

已知模式：macOS 上主应用和编辑器子进程可能拥有相同 bundle id，普通“按应用激活”可能落到父窗口。先检查进程树，识别带项目参数的编辑器子进程，再针对具体 PID 激活。

规则：

- 同一工程只保留一个编辑器写实例；
- 不因 Dock 出现两个图标就直接删除工程或缓存；先确认它们是否为主进程和编辑器子进程；
- UI 自动化前截图并确认窗口标题、工程名和当前页面；
- 不永久硬编码点击坐标。窗口位置、缩放和编辑器版本变化时重新测量；
- 键盘焦点可能漂移到其他应用，输入前再次激活目标进程。

运行 `scripts/inspect_douyin_runtime.py` 获取只读进程和日志线索。

## 3. 加载和编译

症状：场景加载失败、预览空白、脚本无反应。

按顺序检查：

1. 当前工程路径是否正确；
2. 是否有两个编辑器实例同时写同一 `Library/CacheData`；
3. 最新日志中是否明确记录工程打开成功；
4. 修改素材是否出现 `import_start` / `import_end`；
5. TypeScript 是否出现 `compiled success` 或明确错误；
6. 主场景和脚本引用是否仍存在；
7. 冷启动是否能消除仅存在于编辑器状态的故障。

不要在未备份且未确认目标的情况下删除整个 `Library` 或其他缓存。需要清理时先说明范围和可恢复方式。

## 4. 素材与引用

症状：替换图片后没有变化、透明背景变黑、显示旧文案、图标不更新。

检查：

- 源位图是否真的位于当前工程 `Assets`；
- 同名 `.extra` 是否存在，GUID 是否保持一致；
- PNG 尺寸、Alpha、颜色模式和压缩设置是否符合使用场景；
- 文案是否烘焙在图片中，而不是编辑器文本节点；
- 导入日志是否指向修改后的绝对路径和预期 GUID；
- 场景是否引用另一个同名资源或重复哈希资源。

替换后必须在真实预览中触发对应画面，不以素材库缩略图为验收。

## 5. 场景对象完整性

症状：层级中有图片节点、参数面板能看到已绑定素材、脚本也能切换显隐，但中央场景和预览始终只有默认人物。

这类节点可能是“幽灵节点”：编辑器能够解析序列化字段，但渲染引擎没有获得完整、由编辑器生成的对象关系。常见诱因包括从零手写 `main.scene` / `main.scene.extra`、编造规律 GUID、只复制场景文件而遗漏依赖，或把普通 `Transform` 当作 2D 根画布。

硬规则：

- 不从零手写实体、`ImageRenderer`、`ScreenTransform`、对象 GUID 或资源 GUID；
- 使用像塑实际创建的节点，或从已在编辑器/手机真实显示过的工程整体复用原生骨架；
- 复用时保留 `main.scene`、`main.scene.extra` 与依赖素材/子图之间的原始关系，只改必要业务字段；
- 先让一张高对比全屏图覆盖默认摄像头，再接脚本和批量素材；
- 两次冷启动仍失败时停止局部补丁，备份后换完整原生骨架；
- “节点存在”“纹理已绑定”“编译成功”“显隐日志正确”都不能替代目标像素截图。

可疑日志包括 `Found invalid object!`、`m_materials is empty`、纹理像素只有占位数据、资源引用缺失。它们可证明场景存在运行时异常，但同类日志也可能出现在旧模板；最终仍以同一反馈环中的视觉变化为准。

## 6. 编辑器预览

症状：中央画布正确，但右侧预览仍显示人物摇头；点击播放无事发生。

区分：

- 中央场景编辑视图；
- 编辑器内置摄像头预览；
- 特效运行状态；
- 手机同步预览。

先确认是否需要点击播放、录制或触发 `RecordStart`。测试互动游戏时必须实际操作，触发胜利和失败。看到静态首帧只证明场景被渲染。

## 7. 手机预览

症状：特效出现在列表但选中后无变化，或提示场景加载失败。

检查：

- 手机选择的是本次最新同步项，而不是多个同名历史项；
- 编辑器和手机处于兼容版本及可用连接状态；
- 包上传/同步是否成功，不把列表图标出现当作场景加载成功；
- 是否需要重拍、切换摄像头或重新进入来触发启动事件；
- 手机端是否能完成一整局，而不只是显示首帧。

反复失败时保存截图、时间点和对应编辑器日志，再建立反馈环；不要盲目重复上传。

## 8. 检测和提交

症状：检测过程中编辑器退出、检测状态消失、点击提交后不确定是否成功。

处理：

- 先保存工程并确认当前修改已经冷启动加载；
- 检测时记录开始截图和最终结果；
- 编辑器退出即记为检测未完成，查看退出前日志；
- 一次干净重试仍退出时，不连续盲点；报告稳定性阻塞并让用户手动复核；
- 提交后寻找明确回执、审核任务或版本记录；仅有上传 URI 不算提交。
