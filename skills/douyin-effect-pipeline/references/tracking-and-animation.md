# 跟踪与动画：分开验证

关键词：鼻子检测、坐标翻转、铲尖、缓存旧帧、卡帧、机械动作。
来源范围：2026-09 大米特效会话，像塑 9.3.2 本地观察；不是所有版本 SDK 的保证。

## TRACK-001：看得到人脸，但道具不在鼻子上

- 症状：角色能显示/跟随，但工具落在鼻梁、眼睛或固定屏幕位置。
- 已观察：该工程曾额外翻转 Y，造成映射错误；调整动画并不能解决检测偏移。
- 排查：真实输入 → 检测有效性/人脸 ID → 原始关键点 → 坐标变换 → 角色局部工具尖端 → 最终渲染。逐层显示调试点，不靠角色位置倒推检测成功。
- 契约：写明每个坐标域的原点、Y 方向、归一化范围、镜像、单位、旋转、pivot。根据当前 SDK/运行输出来确认，不复制历史关键点索引或 `1-y` 公式。
- 验证：中心、左右/上下移动、靠近远离、轻转头、出镜再入镜；分别观察检测点与铲尖误差。阈值按效果尺寸约定，不发明通用精度。
- 边界：2D 遮挡贴图只能形成插入错觉，不是真正 3D 鼻腔几何。改变用户要求的空间效果前先说明。

## ANIM-001：源码帧数变了，实际仍播放旧序列

- 已观察：源序列替换后，原生缓存曾仍提供旧帧数；仅打印自定义数组长度产生假证据。
- 排查：`effectctl assets` 看源帧数 → 原生纹理的实际 `getFrameCount()`（若当前 SDK 支持）→ 播放器 fps/duration/loop → 导入日志 → 连续录屏。
- 修复：先确认工程/PID/引用，保存并停止对应写实例后，必要时进行范围明确、可回退的重导入；不要直接删整个工程缓存碰运气。
- 验证：源帧数与运行帧数一致，且帧索引持续推进；源码一致仍不能证明运行素材内容一致，需抽帧或录屏检查。
- 边界：序列 `.otextureseq.folder` 内部帧不一定各有 `.extra`；重复帧可能是有意停顿，不应自动删除。

## ANIM-002：整体平移、随机变速依然像机器人

- 已观察：整体位移不能替代持物肢体运动；固定铲尖的补偿也曾抵消真正的掏动；只平滑最终姿态会抹掉短促动作。
- 实现选择：先确认素材是否包含动作。骨骼驱动、分层关节、烘焙序列各有边界；不能把序列贴图描述为实时生成 3D 模型。
- 验证维度：爪子握点与工具一致、头部注视目标、肩肘腕协同、身体反作用、动作起落与停顿、循环接缝。
- 节奏：有意设计“观察—试探—连续动作—停顿—追加一下”等行为段；随机只用于有边界的变化，不能随机每帧速度造成抖动。
- 同步：尽量用同一时间/实际帧索引驱动肢体、工具尖端和遮挡。跟踪平滑与动作曲线分离。
- 验证：至少连续两个循环，再覆盖移动/丢失/恢复。截图只能证明某个姿态，不能证明流畅、趣味或帧率。录屏前确认编辑器没因失焦暂停。
